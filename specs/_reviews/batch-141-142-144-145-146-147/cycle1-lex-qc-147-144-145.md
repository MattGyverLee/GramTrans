main's copy (lines 425-454) vs the PR's (427-457): every other line identical, including the three assertions of

assertion weakened or removed. "1-line stub" is slightly off (3 lines) but behaviourally one stub. Caveat: file comparison,
not `git diff`.

**2. Consolidation of #147 and #144.**
- Keep `SENSE_LIST_REF_ROW_CAP`, renamed `PREVIEW_REF_ROW_CAP` (keeping `SENSE_LIST_REF_ROW_CAP` as an alias is acceptable
  if the live test needs it). Drop `_REF_DECISION_ROW_CAP`.
- Keep `_capped_rows` as the single helper; delete #144's inline slice.
- Make #144's section renderer cap per action kind via `_capped_rows`, matching #147's design.
- Name collisions:
  - Tests importing `SENSE_LIST_REF_ROW_CAP` / `_capped_rows`: tests/unit/test_issue147_sense_list_row_cap.py:25-26,
    tests/integration/test_issue147_sense_list_row_cap_live.py:157 (constant).
  - Test importing `_REF_DECISION_ROW_CAP`: test_issue144_preview_pos_text_decisions.py:213, :218 -- must be rewritten to
    the surviving constant.
- Merge order: #153 first, then #159 on top (trivial preview.py conflict near `render_preview_extra_lines`). The #144 test
  at :213-218 asserts exactly 25 rows plus "+N more"; its format will change.

**3. Interaction with #146 (PlannedCreate).** (references.py :722-805 in the #146 worktree.)
- (a) #144 does not crash or misname. `_ref_decision_rows` reads only `source_item` and `dropped` (preview.py:2141-2150),
  never `.target_item`. #147 reads only `item_name`/`item_guid` from the records.
- (b) The #144 note is dead. It fires only for a CREATE row with `count>1` (preview.py:2183). Under #146 the first reference
  is a CREATE (count 1) and later ones are separate LINK rows. The unit test at :142-143 passes on a shape that no longer
  occurs. Fix: fire the note when a CREATE row and a LINK row share a GUID; reword.
- (c) #147's collapse wording is false for planned-create LINKs: preview.py:2138-2142 counts planned-create items as
  "already in the target"; itemized Link row :2148 same defect, milder; note :2161 ("show as create") is the opposite of the
  new behaviour. Fix: reword, or subtract GUIDs that have a CREATE row. Neither renderer can see `PlannedCreate` today
  (target_item=None); cleaner fix is a `planned: bool` on `ReferenceDecision` / `ReferenceDecisionRecord`.
