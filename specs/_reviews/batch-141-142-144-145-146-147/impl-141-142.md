## Root-cause trace
- `preview.py:1495`: `plan_all_lexical_relations(context, _resolver_cache, _dropped)` was a bare statement. Its CREATE records
  (`plan_lexical_relation_decision` -> `ReferenceDecisionRecord(owner_kind="LexReference", action=CREATE)`) were dropped, and
  `RunPlan` had no field to carry them. Only the drops reached Preview, through `_dropped`.
- `_resolve_target_lex_ref_type` leg 4 returns `PLAN_TIME_PENDING` at plan time. `_evaluate_lexical_relation` uses that only for
  the guards' mapping-type fallback, so no record of the type create was made anywhere.
- Move order: `_evaluate_lexical_relation(allow_create=True)` creates the type **before** the pair/tree/zero-member guards.
  Move therefore creates a type even when its only relation is then dropped, and Preview has to predict the create at the same point.

## Fix
- categories.py:
  - New `_LEXREF_TYPE_PENDING_KEY`.
  - `_evaluate_lexical_relation(..., pending_types=None)` records `{type_guid: label}` when a plan-time resolution returns
    `PLAN_TIME_PENDING`, right after resolution and before the guards. Move callers don't pass it, so Move is unchanged.
  - `plan_lexical_relation_decision` passes `resolver_cache.setdefault(_LEXREF_TYPE_PENDING_KEY, {})` and fills
    `item_name` with the relation type label. It was "" before; no test asserted on it.
  - `plan_all_lexical_relations` emits one `ReferenceDecisionRecord(owner_kind="LexRefType", field_name="PossibilitiesOS",
    action=CREATE, item_name=label, item_guid=type_guid)` per pending type, placed before that type's first relation.
    Records are deduplicated per call by type GUID.
- models.py: `RunPlan.lexical_relation_decisions: tuple = ()`, appended at the end of the dataclass.
- preview.py (changes kept local): the call site captures the return value; one new kwarg on the `RunPlan(...)` call; new
  `render_lexical_relation_decisions(plan)` (header "  Lexical relations:", one line per new type, one grouped
  "Create N relation(s) of type 'X'" line per type, `()` when empty); one appended line in `render_preview_extra_lines`.
  `_resolver_cache` priming is untouched (#146).
